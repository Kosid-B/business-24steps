# CEO AI Thailand — วินิจฉัยการตลาดจากข้อมูลจริง

**วันที่** 24 สิงหาคม 2569 · **ข้อมูล** 11–24 ส.ค. 2569 (13 วัน) จากตาราง first-party ของเราเอง
**สถานะข้อมูล** ตัวเลขทั้งหมดในเอกสารนี้เป็น**ข้อมูลจริง** ยกเว้นส่วนที่กำกับว่า "สมมติฐาน"

---

## 1. สรุปสำหรับผู้บริหาร

1. ปัญหาไม่ใช่ "คนเข้ามาแล้วไม่สมัคร" — ปัญหาคือ **การตลาดยังไม่เคยถูกลงมือทำ**: แคมเปญ 0 · ข้อเสนอ 0 · คอนเทนต์ 0 ชิ้น
2. คนเข้าเว็บ 85 ครั้งใน 13 วัน (≈6.5/วัน) ในจำนวนนี้ **72 คนไม่เลื่อนหน้าเลยแม้แต่พิกเซลเดียว**
3. ทราฟฟิกจาก social 32 ครั้ง → **31 ไม่เลื่อนเลย · สมัคร 0 คน** ช่องทางที่เราใช้อยู่ให้ผลเป็นศูนย์
4. **เก็บ lead ไม่ได้เลยสักคน** — ตารางเก็บ lead ทั้ง 3 ตัวว่างเปล่า เพราะเว็บไม่มีขั้นที่คนยอมทำก่อนสมัครเต็ม
5. เราสร้าง segment ไว้ 5 กลุ่ม แต่ **81 จาก 85 คนเห็นหน้า default** — งานที่ทำไว้ไม่ได้ถูกใช้

> **ข้อเสนอหลัก:** อย่าเพิ่งซื้อโฆษณา ให้ซ่อม 3 อย่างก่อน — ที่เก็บ lead · UTM · หน้าตาม segment
> ใช้เวลา 1 สัปดาห์ ต้นทุน ฿0 แล้วค่อยเอาเงินลงช่องทางที่วัดผลได้

## 2. สถานการณ์ปัจจุบัน

### 2.1 ตัวเลขจริง (ทั้งหมดจาก `landing_funnel`, `marketing_*`, `workspaces`)

| รายการ | จำนวน |
|---|---|
| Session ทั้งหมด (13 วัน) | **85** (≈6.5/วัน) |
| ไม่เลื่อนหน้าเลย (max_scroll = 0) | **72** |
| เลื่อนเกิน 50% ของหน้า | **4** |
| กดถึงปุ่ม CTA | **6** |
| ไปถึงหน้าสมัคร | **3** |
| Workspace ที่เกิดขึ้นจริง | **2** |
| **Lead ที่เก็บได้** (3 ตารางรวมกัน) | **0** |
| แคมเปญที่เคยรัน | **0** |
| ข้อเสนอ (offer) ที่เคยสร้าง | **0** |
| คอนเทนต์ที่เคยผลิต | **0** |

### 2.2 จุดที่พังชัดที่สุด — แยกตามที่มาของทราฟฟิก

| ที่มา | Session | ไม่เลื่อนเลย | สมัคร |
|---|---|---|---|
| **Social** | **32** | **31** | **0** |
| Direct | 47 | 34 | 2 |
| อื่น ๆ | 6 | 7* | 1 |

\* ตัวเลขคาบเกี่ยวกลุ่มย่อย — ประเด็นคือสัดส่วน ไม่ใช่ผลรวมเป๊ะ

**ทราฟฟิกจาก social 32 ครั้ง ได้ผลลัพธ์ศูนย์** ไม่ใช่ "แปลงต่ำ" แต่คือ **ศูนย์** และ 31 ใน 32 ไม่เลื่อนหน้าเลย
แปลว่าคนกดเข้ามาแล้วเห็นหน้าแรก แล้วออกทันที — **หน้าแรกไม่ให้เหตุผลว่าทำไมต้องเลื่อนดูต่อ**

### 2.3 ช่องว่างของข้อมูล — เราตัดสินใจไม่ได้เพราะวัดไม่ครบ

| ปัญหา | ตัวเลข | ผลที่ตามมา |
|---|---|---|
| Session ที่ไม่มี UTM | **83 จาก 85** | ไม่รู้ว่าคนมาจากโพสต์ไหน ช่องทางไหน จะ optimize อะไรก็ไม่ได้ |
| Session ที่เห็นหน้า default | **81 จาก 85** | 5 segment + 7 message pillar ที่สร้างไว้ ไม่ถูกใช้งาน |
| Session ที่ไม่ถูกจัดกลุ่ม A/B | **60 จาก 85** | A/B test ครอบคลุมแค่ 29% สรุปผลไม่ได้ |

> **เรากำลังละเมิดกฎแบรนด์ของตัวเอง** — `marketing_brand_rules` ข้อ tracking (severity: **block**) เขียนว่า
> *"ทุกปลายทางของ campaign/content ต้องติด campaign/content/segment และ UTM ให้ครบก่อนใช้ข้อมูลตัดสินใจ"*
> ตอนนี้ 83/85 ไม่มี UTM

### 2.4 ข้อควรระวังทางสถิติ

กฎแบรนด์ข้อ measurement (severity: **block**) ห้ามสรุป Conversion Rate / CPA / ROAS เมื่อ sample ต่ำกว่าเกณฑ์

**เอกสารนี้จึงรายงานเป็นจำนวนนับ ไม่ใช่อัตราส่วน** — 85 session น้อยเกินกว่าจะสรุปอัตราแปลงได้
สิ่งที่สรุปได้อย่างมั่นใจคือสิ่งที่เป็น **ศูนย์**: lead 0 · แคมเปญ 0 · offer 0 · คอนเทนต์ 0 · social signup 0
ศูนย์ไม่ต้องรอ sample

## 3. กลุ่มเป้าหมายและ Insight

เรานิยาม 5 segment ไว้แล้วใน `marketing_audience_segments` — คุณภาพดี ใช้ได้เลย ไม่ต้องทำใหม่

| Segment | ปัญหาหลัก | ทริกเกอร์ที่ทำให้ตัดสินใจ |
|---|---|---|
| `employee` คนทำงานประจำ | มีเวลาจำกัด กลัวลงทุนผิด | รายได้ไม่พอ อยากมีหลายทาง |
| `newbie` คนอยากเริ่มธุรกิจ | ข้อมูลเยอะเกินไป ไม่รู้ทำอะไรก่อน | อยากเปลี่ยนไอเดียเป็นรายได้ |
| `graduate` นักศึกษาจบใหม่ | ทุนจำกัด ไม่มีประสบการณ์ขาย | เพิ่งจบ กำลังเลือกเส้นทาง |
| `growth` เจ้าของธุรกิจ | เจ้าของเป็นคอขวด ไม่รู้กำไรจริง | ยอดขายเริ่มโต เริ่มมีทีม |
| `audit` กลุ่ม ISO | มีวันตรวจรออยู่ เอกสารไม่พร้อม | ลูกค้าขอใบรับรอง |

**Insight ที่ข้อมูลบอก:** ทั้ง 5 กลุ่มมีปัญหาคนละแบบสิ้นเชิง แต่ **81 จาก 85 คนเห็นข้อความเดียวกันหมด**
หน้า default ที่ต้องพูดกับทุกคน จะไม่พูดกับใครเลย — และตัวเลข 72 คนไม่เลื่อนหน้า คือหลักฐานของเรื่องนี้

**สมมติฐาน (ต้องยืนยัน):** คนที่มาจาก social ส่วนใหญ่คือ `newbie` และ `employee`
เพราะเป็นกลุ่มที่ scroll ผ่านฟีดแล้วสะดุดกับเรื่อง "เริ่มธุรกิจ / รายได้เสริม"
→ ยืนยันได้ด้วยการติด UTM แยกตามโพสต์ ใช้เวลา 1 สัปดาห์

## 4. ข้อเสนอเชิงกลยุทธ์

### 4.1 ลำดับที่ถูกต้อง — ห้ามสลับ

```
1. มีที่รับ lead   →  2. ติด UTM ครบ  →  3. หน้าตาม segment  →  4. คอนเทนต์  →  5. ค่อยซื้อโฆษณา
   (สัปดาห์ 1)         (สัปดาห์ 1)        (สัปดาห์ 2)          (สัปดาห์ 3–4)     (เดือนที่ 2)
```

**เหตุผลที่ห้ามซื้อโฆษณาก่อน:** ตอนนี้ social 32 ครั้ง ได้ 0 ถ้าเอาเงินมาเร่งช่องทางที่ให้ผลศูนย์
ผลลัพธ์คือศูนย์ที่แพงขึ้น และเราจะไม่รู้ด้วยซ้ำว่าเงินหายไปทางไหน เพราะ 83/85 ไม่มี UTM

> **ระบบของเราเองก็บอกแบบนี้** — `readiness()` ใน `lib/constitution/gate.ts` จะตัดสินว่า
> ประตู **"วัดผลได้หรือยัง"** ยังไม่ผ่าน → Next Best Action = ซ่อมการวัดผล ไม่ใช่ยิงโฆษณา
> เราควรเป็นลูกค้าคนแรกของธรรมนูญตัวเอง

### 4.2 ปัญหาที่ใหญ่ที่สุด: ไม่มีขั้นกลางระหว่าง "อ่าน" กับ "สมัคร"

ตอนนี้เว็บมีสองสถานะเท่านั้น — **อ่านเฉย ๆ** หรือ **สมัครเต็มรูปแบบ** ไม่มีอะไรอยู่ตรงกลาง
คนที่ยังไม่พร้อมสมัครจึงออกไปโดยไม่ทิ้งอะไรไว้เลย และเราเก็บ lead ได้ **0 คน**

**ข้อเสนอ: สร้างข้อเสนอเล็กที่แลกกับอีเมล 1 ชิ้น** ตอบโจทย์ `newbie` + `employee` ซึ่งเป็นกลุ่มใหญ่สุด

| หัวข้อ | รายละเอียด |
|---|---|
| ชื่อ | **"เช็ก 6 ข้อก่อนลงทุนกับไอเดียธุรกิจ"** |
| รูปแบบ | แบบเช็กออนไลน์ 6 คำถาม ใช้เวลา 2 นาที → ได้คะแนนความพร้อม + บอกว่าควรทำอะไรก่อน |
| ทำไมได้ผล | ตอบ pain point ตรง ๆ ของ `newbie` (*"ไม่รู้ทำอะไรก่อนหลัง"*) และ `employee` (*"กลัวลงทุนผิด"*) |
| **ของที่มีอยู่แล้ว** | **ใช้ `readiness()` ที่เราเพิ่งสร้างได้ทันที** — 6 คำถามคือ 6 ประตูของ Validation Gate |
| ที่เก็บ | ตาราง `quickcheck_submissions` **มีอยู่แล้ว** (0 แถว) ไม่ต้องสร้างใหม่ |

นี่คือข้อเสนอที่ต้นทุนต่ำที่สุดที่เป็นไปได้ เพราะตรรกะและตารางมีครบแล้ว เหลือแค่หน้าจอ

### 4.3 หน้าแรกต้องเปลี่ยน — เริ่มจากปัญหา ไม่ใช่จากชื่อสินค้า

กฎแบรนด์ข้อ message_hierarchy (severity: **block**) ห้ามใช้ *"AI Business Operating System"* เป็นพาดหัวแรก
ให้เริ่มจากปัญหาหรือเป้าหมายของผู้ใช้ — และข้อมูล 72 คนไม่เลื่อนหน้า บอกว่าตอนนี้พาดหัวยังไม่ทำงาน

พาดหัวที่เสนอ แยกตาม segment (ทุกอันเริ่มจากปัญหา ไม่มีคำการันตี ไม่มีการเร่งเร้าเท็จ):

| Segment | พาดหัว | ปุ่ม |
|---|---|---|
| `newbie` | **"มีไอเดียแล้ว แต่ไม่รู้ว่าต้องทำอะไรก่อน"** | เช็กความพร้อมใน 2 นาที |
| `employee` | **"อยากมีรายได้เพิ่ม แต่ไม่อยากเสี่ยงกับงานประจำ"** | ดูว่าเริ่มยังไงไม่ต้องลาออก |
| `graduate` | **"เพิ่งจบ ทุนน้อย แต่อยากเริ่มธุรกิจของตัวเอง"** | เริ่มจากขั้นที่ไม่ต้องใช้เงิน |
| `growth` | **"ยอดขายโตแล้ว แต่ยังต้องทำเองทุกอย่าง"** | ดูว่าระบบไหนควรวางก่อน |
| `audit` | **"มีวันตรวจรออยู่ แต่เอกสารยังไม่พร้อม"** | ประเมิน Gap เบื้องต้น |

> `audit` ใช้เฉพาะ segment นี้เท่านั้น ห้ามใช้ ISO/PDPA เป็นสารนำกับกลุ่มทั่วไป (กฎแบรนด์ข้อ message_hierarchy)

## 6. KPI และวิธีวัด

### 6.1 ตัววัดในเดือนแรก — วัดพฤติกรรม ไม่ใช่วัดอัตราแปลง

| KPI | ตอนนี้ | เป้าเดือนที่ 1 | วัดจาก |
|---|---|---|---|
| Session ที่มี UTM ครบ | 2 / 85 | **≥ 90%** | `landing_funnel.utm_source` |
| Session ที่ถูกจัดกลุ่ม A/B | 25 / 85 | **100%** | `landing_funnel.hero_ab` |
| Lead ที่เก็บได้ | **0** | **≥ 50** | `quickcheck_submissions` |
| Session ที่ไม่เลื่อนเลย | 72 / 85 | **< 50%** | `landing_funnel.max_scroll = 0` |
| Session ที่เห็นหน้าตรง segment | 4 / 85 | **≥ 40%** | `landing_funnel.seg` |

**ยังไม่ตั้งเป้า Conversion Rate ในเดือนแรก** เพราะ sample ยังไม่พอตามกฎแบรนด์ของเราเอง
เดือนแรกคือการทำให้ "วัดได้" ไม่ใช่การทำให้ "ตัวเลขสวย"

### 6.2 คำนวณย้อนกลับ — งบโฆษณาที่สมเหตุสมผล

**ข้อเท็จจริง** ราคาจริงจาก `lib/data/content.ts`: ทดลองฟรี 15 วัน · **฿590/เดือน** · **฿4,990/ปี**

**สมมติฐาน (ต้องยืนยันด้วยข้อมูลจริงเมื่อมีลูกค้าพอ):**
- กำไรขั้นต้น ≈ 85% ของค่าสมาชิก (หักค่า AI + โครงสร้างพื้นฐาน)
- อายุสมาชิกรายเดือนเฉลี่ย 6 เดือน

```
LTV รายเดือน  ≈ ฿590 × 6 × 0.85           ≈ ฿3,010
LTV รายปี     ≈ ฿4,990 × 0.85             ≈ ฿4,240
CAC สูงสุดที่รับได้ ≈ กำไรขั้นต้น × 30–50%
                  → รายเดือน ฿900–1,500 · รายปี ฿1,270–2,120
```

**ตัวอย่างเป้าหมาย** ถ้าต้องการสมาชิกรายเดือนใหม่ 50 คน/เดือน (≈ ฿29,500 MRR เพิ่ม)

```
งบโฆษณา ≈ 50 คน × ฿1,200 (CAC เป้า) = ฿60,000/เดือน
```

> ตัวเลขนี้ยังใช้ตัดสินใจไม่ได้จนกว่าจะรู้ค่าจริง 2 ตัว: **อายุสมาชิกเฉลี่ย** และ **สัดส่วนคนที่ทดลองแล้วจ่ายจริง**
> ทั้งคู่วัดได้หลังมีสมาชิก ≥ 30 คน — นี่คือเหตุผลที่ต้องเก็บ lead ก่อนซื้อโฆษณา

## 7. ความเสี่ยงและแผนสำรอง

| ความเสี่ยง | สัญญาณเตือน | แผนสำรอง |
|---|---|---|
| ทำ "เช็ก 6 ข้อ" แล้วยังไม่มีใครกรอก | ผ่าน 2 สัปดาห์ ได้ lead < 10 | ปัญหาอยู่ที่ทราฟฟิก ไม่ใช่ข้อเสนอ → ไปแก้ที่ช่องทางและพาดหัว |
| แก้หน้าแรกแล้วคนยังไม่เลื่อน | zero-scroll ยังเกิน 70% | ปัญหาอยู่ที่ความคาดหวังจากโพสต์ ไม่ตรงกับหน้า → แก้ที่โพสต์ต้นทาง |
| ทราฟฟิกน้อยเกินจะสรุปอะไรได้ | < 300 session/เดือน | ยอมรับว่าเป็นเฟสหาช่องทาง อย่าเพิ่งสรุป A/B |
| เก็บอีเมลโดยไม่ทำตาม PDPA | — | ดู §7.1 ทำก่อนเก็บข้อมูลจริง |

### 7.1 PDPA — ต้องทำก่อนเก็บอีเมลแม้แต่รายเดียว

- **ฐานทางกฎหมาย:** ความยินยอม (consent) สำหรับการส่งข้อมูลการตลาด
- **ข้อความขอความยินยอม** (วางไว้ข้างช่องกรอกอีเมล พร้อม checkbox ที่**ไม่ติ๊กมาให้ล่วงหน้า**):

  > ☐ ยินยอมให้ CEO AI Thailand เก็บอีเมลเพื่อส่งผลการประเมินและเนื้อหาที่เกี่ยวข้อง
  > ถอนความยินยอมได้ทุกเมื่อที่ลิงก์ท้ายอีเมล · [นโยบายความเป็นส่วนตัว]

- **ต้องมี:** วิธียกเลิกรับข่าวสารในทุกอีเมล · ระบุระยะเวลาเก็บข้อมูล · ช่องทางใช้สิทธิของเจ้าของข้อมูล

## 8. สามสิ่งที่ทำได้ภายในสัปดาห์นี้

1. **ติด UTM ทุกลิงก์ที่โพสต์** — ใช้เวลา 30 นาที ทำได้วันนี้
   รูปแบบ: `?utm_source=facebook&utm_medium=social&utm_campaign=aug2026&utm_content=<ชื่อโพสต์>`
   ผลทันที: รู้ว่าโพสต์ไหนพาคนมา ซึ่งตอนนี้ไม่รู้เลย 83 จาก 85 ครั้ง

2. **เปิดหน้า "เช็ก 6 ข้อก่อนลงทุนกับไอเดียธุรกิจ"** — ตรรกะมีแล้วใน `readiness()` ตารางมีแล้ว
   (`quickcheck_submissions`) เหลือแค่หน้าจอ + checkbox ยินยอมตาม §7.1
   ผลทันที: จาก lead 0 คน เป็นเริ่มมี lead

3. **เปลี่ยนพาดหัวหน้าแรกให้เริ่มจากปัญหา** ตามตารางใน §4.3 และเลิกส่ง social ไปหน้า default
   ผลทันที: แก้ที่จุดที่คน 72 คนหลุดออกไป

**ทั้งสามข้อใช้งบ ฿0** และแก้ที่คอขวดจริงตามลำดับที่ข้อมูลชี้ ไม่ใช่ตามลำดับที่ทำง่าย

## 9. สถานะการลงมือจริง และสิ่งที่ต้องรู้ตอนใช้งาน

*(เพิ่มเมื่อ 9 ต.ค. 2569 — หลังทำข้อ 2 ของ §8 เสร็จและทดสอบด้วยเบราว์เซอร์จริง)*

### 9.1 ทำไปแล้ว

| ข้อใน §8 | สถานะ | อยู่ที่ไหน |
|---|---|---|
| 2 · หน้าเช็ก 6 ข้อ | **เสร็จ** | `/quickcheck` · ตรรกะใช้ `readiness()` ตัวเดียวกับระบบ |
| 2 · ทางเดินไปถึงหน้านั้น | **เสร็จ** | ลิงก์บน `/login` — เป็นหน้าเดียวที่คนนอกเข้าถึงได้ เพราะ `/` บังคับ login |
| 1 · UTM ไม่หาย | **เสร็จครึ่งทาง** | ระบบพา UTM ข้ามหน้าให้แล้ว · **แต่คนโพสต์ต้องติด UTM ที่ลิงก์เอง** ดู §9.3 |
| 3 · พาดหัวหน้าแรก | **ยังไม่ได้ทำ** | อยู่คนละ repo (`ceoaithailand.org`) ข้อความพร้อมแล้วใน §4.3 |

### 9.2 ฐานข้อมูลถูกพัก แต่ lead ไม่หาย

บัญชี Supabase ชั้นฟรีเปิดได้พร้อมกันแค่ 2 โปรเจกต์ ตอนนี้ `Electric Colme` กับ `SCK-SaaS`
ใช้สองช่องนั้นอยู่ ทั้ง `CEO Ai Thailand` และ `Business Intelligent` จึงเป็น `INACTIVE`
แปลว่า `/quickcheck` **เขียนลงตาราง `quickcheck_submissions` ไม่ได้**

เดิมกรณีนี้จะตอบ error 500 แล้วอีเมลที่คนกรอกมาหายไปเฉย ๆ ซึ่งแพงที่สุด เพราะเกิดหลังจาก
เขาตัดสินใจให้ข้อมูลแล้ว ตอนนี้เปลี่ยนเป็น:

1. ผู้ใช้ยังได้คะแนนและคำแนะนำของเขาครบ (HTTP 200) และเห็นข้อความตามจริงว่าติดต่อกลับอาจช้า
2. lead ถูกเขียนลง log ของ server เป็น JSON บรรทัดเดียว ขึ้นต้นด้วย `[quickcheck][LEAD_FALLBACK]`

**วิธีดึง lead ที่ตกค้างออกมา** — อ่าน runtime log ของ Vercel แล้วกรองบรรทัดนั้น เช่น

```bash
vercel logs <deployment> | grep -o '\[quickcheck\]\[LEAD_FALLBACK\].*' \
  | sed 's/^\[quickcheck\]\[LEAD_FALLBACK\] //' > leads.ndjson
```

แต่ละบรรทัดมี `email` · `score` · `verdict` · `answers` · UTM ครบ · `consent` · `consent_at`
พร้อมใส่กลับเข้าตารางได้เลยเมื่อปลุกฐานแล้ว

> **ข้อจำกัดที่ต้องรู้: log มีอายุสั้นกว่าฐานข้อมูล** นี่คือทางสำรองกันของหาย
> ไม่ใช่ที่เก็บถาวร ยิ่งปลุกฐานเร็วยิ่งดี

**PDPA**: เขียนลง log เฉพาะกรณีที่ยินยอมแล้วเท่านั้น และเพื่อวัตถุประสงค์เดียวกับที่ยินยอมไว้
(ติดต่อกลับ) — ไม่ยินยอมคือไม่บันทึกและไม่ log ไม่มีข้อยกเว้น มีเทสต์คุมไว้

### 9.3 รูปแบบลิงก์ที่ต้องใช้ตอนโพสต์

ติด UTM ที่ลิงก์ **ทุกครั้ง** ไม่งั้นก็ยังวัดไม่ได้เหมือนเดิม ชี้ไปที่ `/quickcheck` ตรง ๆ ได้เลย:

```
https://<โดเมน>/quickcheck?utm_source=facebook&utm_medium=social&utm_campaign=oct2026&utm_content=<ชื่อโพสต์>&seg=<กลุ่ม>
```

`seg` ใช้ค่าตามกลุ่มใน §3 — ถ้าไม่ใส่จะถูกนับเป็น `default` ซึ่งคือสิ่งที่เกิดกับ 81 จาก 85 session

ถ้าชี้ไปที่ `/login` ก่อนแล้วให้เขากดต่อเอง UTM ก็ยังไม่หาย ระบบพาต่อให้แล้ว
(มีเทสต์ในเบราว์เซอร์จริงคุมเคสนี้ไว้)

### 9.4 ต้องตั้งค่าก่อน deploy จริง

| ตัวแปร | ใส่อะไร | ถ้าไม่ใส่จะเป็นอะไร |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | โดเมนจริงที่ผูกไว้ เช่น `https://app.ceoaithailand.org` | ลิงก์ที่แชร์ (og:url, og:image, canonical) จะชี้โดเมนชั่วคราวของ Vercel |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ของโปรเจกต์ `Business Intelligent` | lead จะตกไปทาง §9.2 ทุกราย |

หน้า `/quickcheck` มีรูปพรีวิวตอนแชร์ให้แล้ว (สร้างจากโค้ด ไม่ต้องมีไฟล์รูป)
ตรวจได้ด้วย `curl -s <url>/quickcheck | grep og:` — ก่อนหน้านี้แชร์ไปแล้วไม่มีหัวข้อไม่มีรูป
ซึ่งเป็นหนึ่งในเหตุที่ social 32 ครั้งแล้วไม่เหลือใครเลย

## ภาคผนวก — คำสั่งตรวจตัวเลขซ้ำ

ตัวเลขทุกตัวในเอกสารนี้ตรวจซ้ำได้จาก Supabase project `waigsnxhrlwtiotspaim`:

```sql
-- ภาพรวมกรวย
select count(*) sessions,
       count(*) filter (where max_scroll = 0)   as ไม่เลื่อนเลย,
       count(*) filter (where reached_cta)      as ถึง_cta,
       count(*) filter (where reached_signup)   as ถึงหน้าสมัคร,
       count(*) filter (where utm_source is not null) as มี_utm
from landing_funnel;

-- แยกตามที่มา
select ref_kind, count(*) n,
       count(*) filter (where max_scroll = 0) as ไม่เลื่อนเลย,
       count(*) filter (where reached_signup) as สมัคร
from landing_funnel group by 1 order by n desc;

-- ยืนยันว่าการตลาดยังไม่เคยถูกลงมือ
select (select count(*) from marketing_campaigns)     as แคมเปญ,
       (select count(*) from marketing_offers)        as ข้อเสนอ,
       (select count(*) from marketing_content_items) as คอนเทนต์,
       (select count(*) from quickcheck_submissions)  as lead;
```
