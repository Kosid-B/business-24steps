เอกสารนี้ตอบคำถามเดียว: **ธรรมนูญแต่ละข้อ ต้องไปอยู่ตรงไหนของระบบ และตอนนี้ขาดอะไร**

สำรวจเมื่อ 2026-08-24 · ตัวเลขแถวเป็นค่าที่อ่านจากฐานจริงในวันนั้น

## ข้อค้นพบที่เปลี่ยนลำดับความสำคัญทั้งหมด

## Mindset แต่ละข้อ → ต้องเห็นเป็นอะไรในระบบ

| หลัก | ต้องเห็นเป็นอะไร | ตอนนี้ | ช่องว่าง |
|---|---|---|---|
| First Principles | ทุกคำแนะนำอ้างหลักฐานที่มาได้ | ยังไม่มีระบบอ้างอิง | ต้องมี `evidence_id` ผูกกับคำแนะนำ |
| 10x Thinking | เทียบกับ benchmark ไม่ใช่กับตัวเองเมื่อวาน | `industry_benchmarks` ว่าง | รอข้อมูล genome ถึงเกณฑ์ n≥30 |
| Experiment Fast | สมมติฐาน → การทดลอง → ผล | ขั้น 20/21 มีในหลักสูตร แต่ไม่ถูกเก็บเป็นข้อมูล | ผูกขั้น 20/21 เข้า `marketing_experiments` |
| **Evidence > Opinion** | หลักฐานเป็นวัตถุที่มีชนิด แหล่งที่มา วันที่ ความเชื่อมั่น | เก็บเป็นข้อความอิสระ | **ช่องว่างใหญ่ที่สุด — ดูข้างล่าง** |
| Failure = Learning Data | การทดลองที่ไม่ผ่านและการข้าม Gate ถูกบันทึก | `describeSkip()` พร้อมแล้ว แต่ยังไม่มีที่เก็บ | ต้องมีตารางเก็บ skip |
| Compounding Learning | ทุก outcome ป้อนกลับเข้า Decision Engine | ยังไม่มีลูปนี้ | ต้องมีข้อมูลก่อน |

## ช่องว่างที่ใหญ่ที่สุด: หลักฐานยังไม่ใช่วัตถุ

ตอนนี้คำตอบของแต่ละขั้นเก็บแบบนี้ (`types/index.ts`):

```ts
export interface StepProgress {
  done: boolean
  data: Record<string, string | string[]>
}
```

`done` เป็น checkbox · `data` เป็นข้อความอิสระ — **ไม่มีที่เก็บว่า** หลักฐานคืออะไร
มาจากไหน เก็บเมื่อไร เชื่อได้แค่ไหน มีไฟล์แนบไหม

ผลที่ตามมา: `hasEvidence()` ใน `lib/constitution/gate.ts` ตรวจได้แค่ว่า
*"มีเนื้อหาหรือเปล่า"* ตรวจ *"คุณภาพ"* ไม่ได้ — และนี่คือข้อจำกัดที่ยอมรับไว้แล้ว
ในธรรมนูญข้อ 10

### สิ่งที่ต้องมี (รอบถัดไป)

ตารางหลักฐานที่แต่ละแถวคือหลักฐานหนึ่งชิ้น อย่างน้อยต้องมี:

| คอลัมน์ | ทำไมต้องมี |
|---|---|
| `step_no` | ผูกกับขั้นในหลักสูตร |
| `gate_id` | ผูกกับประตูใน `GATES` |
| `kind` | สัมภาษณ์ / ยอดขาย / มัดจำ / ผลทดลอง / ข้อมูลตลาด |
| `source` | ใครให้ข้อมูล เก็บอย่างไร |
| `collected_on` | หลักฐานเก่าต้องมีน้ำหนักน้อยลง |
| `confidence` | ผู้ก่อตั้งประเมินเอง แล้วให้ระบบท้าทาย |
| `attachment_url` | ไฟล์/ภาพ/ลิงก์ |

เมื่อมีตารางนี้ `hasEvidence()` จึงเปลี่ยนจาก "นับตัวอักษร" เป็น "นับหลักฐานจริง" ได้
โดย**ไม่ต้องแก้ตรรกะของ Gate เลย** — เพราะ `readiness()` รับข้อมูลผ่าน interface
`ReadinessInput` ที่แยกจาก `AppState` อยู่แล้ว

return done * 100 + lessons * 40 + matches * 120 + bookings * 60

### ทางเลือกในการแก้ (ยังไม่ทำ — ต้องให้เจ้าของโปรเจกต์ตัดสิน)

| ทาง | ทำอะไร | ผลกระทบผู้ใช้เดิม |
|---|---|---|
| **A. เพิ่มแกนใหม่ (แนะนำ)** | เก็บ XP เดิมไว้ แล้วเพิ่ม **Evidence Level** จาก `readiness().score` แสดงคู่กัน | ไม่มีใครเสียยศ · เริ่มได้ทันที |
| B. ถ่วงน้ำหนักใหม่ | คูณ XP ของแต่ละขั้นด้วย `hasEvidence()` | ผู้ใช้เดิมยศตก อาจเสียความรู้สึก |
| C. รีเซ็ตทั้งหมด | คิดใหม่จากหลักฐานล้วน | รุนแรงที่สุด ควรทำเฉพาะตอนยังมีผู้ใช้น้อย |

ตอนนี้มีผู้ใช้ในฐาน BI เพียง 1 ราย (`members` = 1, `ide_projects` = 1)
→ **ต้นทุนการเปลี่ยนตอนนี้ต่ำที่สุดเท่าที่จะเป็นไปได้ และจะแพงขึ้นทุกวัน**

## ลำดับที่แนะนำสำหรับรอบถัดไป

1. **ตารางหลักฐาน** — ทำให้ "Evidence > Opinion" เขียนลงระบบได้จริง
2. **ต่อ `readiness()` เข้าหน้าจอ** — หน้าแผน/โค้ช แสดงคะแนนความพร้อมและ Next Best Action
3. **บันทึกการข้าม Gate** — `describeSkip()` มีแล้ว เหลือที่เก็บ (นี่คือแถวแรกของ Outcome Dataset)
4. **ตัดสินใจเรื่อง XP** — เลือกทาง A / B / C
5. **ผูกขั้น 20–21 เข้า `marketing_experiments`** — เปลี่ยนแบบฝึกหัดให้เป็น Experiment Memory
6. **รวมฐานหรือแบ่งหน้าที่ให้ชัด** — ตัดสินใจเรื่องสองฐานก่อนที่ข้อมูลจะเริ่มไหล

ข้อ 1–3 ทำได้โดยไม่ต้องตัดสินใจเรื่องฐานก่อน
